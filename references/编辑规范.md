# 外贸情报局周刊 · 编辑规范

> **定位：选品用的外贸市场周情报，看广度和方向，不做单品深挖。**每周扫一遍收款安全的国家，找出**现在缺什么、接下来会缺什么**，排出「品类 × 国家」机会榜。
> 查进口商名单、联系人、专利、Trade Map 这类细查，等周刊主人锁定某个品类后再做（见 `锁定品类后深挖.md`），不放进周刊。
> 下面的 `$SKILL` = 本 skill 目录，`$P` = 周刊文件夹。

---

## 一、盯哪些国家（贸易安全名单）

名单在 `$P/config.json` 的 `regions`，默认 7 个区域 32 国。

标准：Allianz Trade 国家评级 **AA / A 档**（收钱安全），再叠加对华政策风险。**每季度复查一次**评级（Allianz、Coface 各看一份），复查后改 `config.json` 的 `regions` 和 `safe_list_checked`；遇到战争、制裁这类突发事件，当周就在「国别风险」里标出来。

| 区域 | 需求共性 |
|---|---|
| 北美 | 量最大，价格敏感，大促驱动。美国付款安全，关税政策不稳 |
| 德语区 + 荷比卢 + 中东欧 | 重认证、重环保，欧盟法规最先落地 |
| 北欧 + 波罗的海 | 极简、可持续，冬季长 |
| 英爱 | 英语市场，电商渗透高，英国法规独立 |
| 南欧 | 户外、餐饮、旅游业，夏季品 |
| 日韩 | 标准极高，偏小尺寸、精细化 |
| 大洋洲 + 枢纽 | 澳新季节和北半球相反；新加坡、阿联酋是转口枢纽 |

`选品档案.md` 填了优先市场的，机会榜照样 32 国同一把尺子打分；只在两个候选机会分接近时，把优先市场排前面，并在卡片标题上标 ⭐。

## 二、信号源（默认全部免费）

### 消费端：消费者在搜什么、买什么、吐槽什么（周刊主体，不能省）

| 源 | 怎么取 | 看什么 | 覆盖 |
|---|---|---|---|
| **Google 购物搜索飙升词** | `shopping_rising.py $P` | **发现层**：不用预设关键词，直接看消费者这周突然在搜什么商品 | config 里的 11 国 × 7 品类 |
| **折扣社区热榜** | `deals_collect.py $P` 收，`deals_summary.py $P` 汇总 | 热度（°）= 用户投票。看哪些品类被抢、什么价位成交 | 英 hotukdeals、德 mydealz、奥 preisjaeger、法 dealabs、西 chollometro、荷 pepper、美 Slickdeals、加 RedFlagDeals |
| **亚马逊畅销榜、新品榜周对比** | `amazon_bestsellers.py $P` | **发现层 +「已经在买」层**：畅销榜前 50 名和上次比，新上榜、名次涨 ≥10、跌出前 20；**新品榜**看刚上架、评价还少的新品，白牌新品在这里比畅销榜早冒头；**价格连续变动**（同一商品连续两周同向、累计 ≥10%，大促期间不比） | config 里的类目 × 美英德法；新品榜按 `amazon_new_releases` |
| Reddit 消费类板块（可选） | `reddit_scan.py $P`，高赞帖用 `rdt read <ID>` 读评论 | **痛点层**：产品哪里不好用、想买买不到、准备囤什么 | BuyItForLife、Frugal、HomeImprovement 等 |
| Google Trends 同比 | `google_trends_yoy.py 国家 词1 词2…`，**每期最多 20 组** | **验证层**：发现层冒出来的词，查是不是真趋势 | 全部 |
| **官方进口数据** | `import_stats.py 税号 国家…` | **验证层（硬数据，不靠谷歌）**：某个税号今年累计和去年同期比，从中国、从美国进口多少，中国份额怎么变。**只查机会榜前 3 名** | 美国（要免费 API key）、加拿大、英国、欧盟各国；最新约晚 1–3 个月。税号粗，不适合用来发现 |
| 亚马逊搜索页抽样 | `amazon_search_sample.py 国家 "关键词"`，**每期最多 10 次** | **验证层**：第一页价格带、「过去一月购买」量级、头部是不是中国卖家、「顾客怎么说」里的负面（= 产品痛点） | 美、加、德（有痛点标签）；意、西、荷、比（没有痛点标签）。英、法、澳会被拦 |

消费端写作要求：
- **需求先行，先列「本周需求总表」**：去掉噪音（球赛、手机和汽车型号、优惠码、店名、"your orders"）后，购物飙升词、畅销榜新上榜和大涨、新品榜前 20 名里冒出来的**所有品类词、产品词**都按品类归进总表，注明哪几国在涨，只有一国的标「单国」，**不看适配度**。品牌和型号词（Ninja、Dyson、Nike）不算品类机会，在总表最后单列一行
- 总表里的需求，至少 2 个国家同时出现，或同一国家几个相关词一起涨，才写成「消费 0X」信号。总表里连续 2 周以上出现的品类记进信号台账
- **适配度不用来砍需求**：重货、要认证、季节性强、不合选品档案的需求，照样写进总表和消费动向，适配度只在机会榜排序时用（碰到选品档案的硬条件才出局）
- **额度先给新信号**：同比和亚马逊抽样的额度，先给本周新冒出来、多国同时出现的词，再给机会榜上的老信号复查；同一个品类一期最多占一半额度。只盯着上期第 1 名反复验证，查得越多证据越多，排名越稳，是确认偏差
- **每月第一期补查慢涨品类**：购物飙升只抓 7 天内突然涨的，慢慢涨的会漏。每月第一期从台账「需求总表里持续出现的品类」各挑 1–2 个代表词查同比，算在同比额度里
- 飙升词的品类筛选是松的：「宠物」组里也会冒出手机、外套。按词本身判断它属于什么品类，不按它出现在哪一组
- 冒出来的爆品要查原因（社媒爆款？季节？政策？），并用同比数据验证
- 畅销榜、新品榜周对比只比同一榜单前后两次；第一次采集没有对比，只列前 10。31–50 名可能只有名次和链接，引用时点链接看。比价格带注意币种
- 官方进口数据单月常有一次性大单或抢关税的突增，判断方向时用 `-v` 看月度明细，写的时候注明；数据晚 1–3 个月，用来复核，不用来发现
- 亚马逊自家设备（Echo、Ring、Blink、Kindle、Fire 等）不当信号。大促周（7 月会员日、10 月秋季会员日、黑五网一）榜单会被自家设备和大促款挤占：在附录标明「本次采集碰上大促」；下期大促款跌出榜单是正常回落，不当成需求下降
- 亚马逊抽样只看第一页，是「现在货架长什么样」的快照，不代表销量排名；「过去一月购买」照抄亚马逊给的区间（如 9K+），不换算。被限流（503 或页面无商品）就停，写进附录，不换方法反复试
- 折扣热榜如果只收到 1 天（没装每天定时），写明「只代表某天某刻的热榜」
- 每条消费端信号都要过一遍**「中国货接不接得住」**：反倾销（例：欧盟对中国电动自行车征税到 2030 年）、专利和外观设计、认证门槛
- Reddit 各国综合板块（r/de、r/france 等）以政治和段子为主，不用；关键词只在 config 里的消费类板块里搜（脚本已经这样做），不做全站搜索

### 采购端：谁在买、处在什么周期、什么时候下单、要什么样的供应商（周刊主体，不能省）

| 源 | 看什么 | 怎么取 |
|---|---|---|
| **零售商、品牌财报和电话会** | 在扩哪些品类、自有品牌比重、库存高低、要不要迁出中国 | 网页搜索、SEC 公告、行业媒体（宠物 GlobalPETS；家居 Sourcing Journal、Retail Dive 等） |
| **库存周期** | 美国零售库存销售比（[FRED RETAILIRSA](https://fred.stlouisfed.org/series/RETAILIRSA)）、美国和欧元区采购经理人指数（PMI）的新订单和库存分项 | 公开数据、新闻 |
| **品类展会日历** | 买家集中看货的时间，样品必须展前备好 | 展会官网，**只用官网核实过的日期** |
| **零售商招聘** | 零售商招某品类的采购、品类经理 = 在扩这个品类 | 零售商**官网招聘页** + 网页搜索公开岗位页。**不用任何工具自动登录周刊主人的 LinkedIn**，会被封号 |
| 亚马逊卖家社区 | 卖家在找什么品、被什么卡住 | Reddit r/FulfillmentByAmazon，信号弱，只作补充 |
| 海关提单、买家名单、采购联系人 | 哪家公司在进口某个 HS 编码、从哪进、进多少；采购和品类经理是谁 | **周刊里不查**，写进「下期跟踪」，锁定品类后再查（见 `锁定品类后深挖.md`） |

**采购端每期至少查 2 个不同品类的零售商或品牌动态**，轮换着查，不要连续几期只查同一个品类：只查一个品类，就只有它可能拿到采购绿灯。

**不用的采购端源**：阿里国际站求购信息（RFQ），虚假信息多；国内论坛、自媒体，营销贴多。

## 三、预测模型：品类 × 国家怎么排序

> **机会分 = 消费需求 × 采购需求 × 可达性 × 时机 × 适配度**
> 五项相乘：任何一项为零（比如被反倾销挡住，或碰到选品档案里的硬条件），整体就是零。每期对候选打 🟢（强）/🟡（中）/🔴（弱）/❓（未验证），排序后放在周刊最前面。

| 因子 | 衡量什么 | 从哪来 |
|---|---|---|
| **消费需求** | 几个国家同时在涨、持续了几周、处在扩散的哪个阶段、**有没有宏观驱动**（有 = 能持续、能预判终点；没有 = 社媒爆款，来去都快） | 消费端各源、同比数据、信号台账 |
| **采购需求** | 零售商在不在扩这个品类、补库还是去库、有没有在换供应商。消费端热、采购端冷（货已备足）= 时机未到 | 采购端；官方进口数据（从中国进口在涨、中国份额在升 = 采购方真的在多买） |
| **可达性** | 反倾销、关税、认证、专利，任何一道关卡挡住就是零。**算挡住**：已经开征的反倾销、反补贴或附加关税（税率高到让中国货没有价格优势，结合这个品类的利润判断，写明理由）；禁令；拿不到的强制认证；有效专利挡着核心结构。**不算挡住、标 🟡 写进风险**：还没开征的初裁、立案调查、只有个别企业税率高 | 风险层 |
| **时机** | B2B 下单窗口开没开：季节、政策截止日、扩散阶段 | 下单日历 |
| **适配度** | `$P/选品档案.md` 的 7 项评分卡加权平均（权重和红绿灯换算写在选品档案里）；碰到「硬条件」直接出局。**只用在机会榜排序，不用来砍需求**：适配度低的需求照样写进需求总表和消费动向 | 选品档案 |

**消费端和宏观怎么连：**
1. **因果**：宏观变化改变消费者处境（能源涨价 → 储能；关税涨价 → 囤耐用品）。宏观解释消费端**为什么动、能动多久**
2. **过滤**：宏观决定中国货接不接得住（例：欧盟对中国电动自行车双反到 2030 年）
3. **时间**：政策公布（提前几个月到几年）→ 搜索上升（提前几周）→ 折扣和销量（当下）→ 海关数据（滞后几个月）。宏观用来提前布局，消费端用来确认，海关数据用来核实规模

**校准**：信号台账记下每期判断。满 8–12 周后回看同比和海关数据，统计判断对了几成，再调因子权重。**校准之前，排序只是有依据的判断，不是验证过的预测**，周刊里不要写得像结论。

## 四、分析框架

### 消费端：每条信号打两个标签
- **扩散阶段**（创新扩散）：尝鲜者（众筹、小众社区）→ 早期采用者（社媒爆火）→ 早期大众（搜索量大涨、上货架）→ 后期大众（进折扣区、打价格战）。**B2B 窗口在「早期采用者到早期大众」之间**；到了后期大众就是红海
- **决策环节**：发现需求 / 搜索（Google 购物）/ 比较（评测）/ 购买（折扣热榜、畅销榜）/ 用后反馈（Reddit 吐槽、亚马逊「顾客怎么说」）
- 用户吐槽用「用户要办成什么事」+「必备属性 vs 加分卖点」翻译成产品规格：哪条是做不到就差评的必备属性，哪条能拿来做差异化

### 宏观：PESTLE
- 周刊层：PESTLE 只当检查清单，附录标出本周六类各覆盖几条，**空着的类要说明是真没有，还是没去看**
- 每条宏观因素都要落到「**哪个品的需求因此变了**」。落不下来就不写（例：「德国人口老龄化」不能单独成条）

## 五、写作纪律

1. **结论在前。**第一屏就是「本期观点」：机会榜 + 行动建议 + 要闻速览，后面才是支撑的信号和数据
   - 机会榜先放一张总览表，每行只有 排名 | 品类 → 国家 | 五个因子的红绿灯 | 一句话结论，**表格里不放链接和长句**
   - 表下面每个候选一张卡片（callout）：前两名用 `> [!success]`、`> [!info]` 展开；其余用 `> [!warning]-`、`> [!failure]-` 折叠。卡片里逐条写五个因子的依据和链接，再写「该找谁」「风险」
   - 「区域速览」也是摘要表，不放链接，每格写一句话加信号编号（例：「慢炖锅在买，见消费 02」），链接都在正文里。每个区域写明消费端看的是哪几国（config 里的国家），**没覆盖的国家没写不等于没机会**
2. **每一条内容都要有可点击的来源链接**，包括正文表格里的数据点（机会榜总览表和区域速览这两张摘要表除外）：
   - 购物飙升词、同比 → 脚本输出的 Google Trends 链接
   - Reddit → 帖子链接；折扣热榜 → 原帖链接；畅销榜 → 商品链接
   - 政策、新闻 → 原文
   - **没有链接的内容不写**
3. **多源印证才标「高」可信度：**
   - 高 = 至少 2 类独立来源指向同一件事（比如政策截止日 + 搜索数据）。**同一个平台的两种数据算一类**：Google 购物飙升词和 Google 同比算一类，标「高」必须另有一个非 Google 的来源（畅销榜或新品榜、折扣热榜、亚马逊抽样、Reddit、官方进口数据）
   - 中 = 1 类硬来源 + 推演，还缺关键核实
   - 低 = 只有推演
   - 消费端信号只有 1 周数据时，最高标「中」
4. **推演被数据否定时写出来**，放进「证伪记录」，不许悄悄删掉
5. 某区域本周没有信号，就写「本周无强信号」，不凑内容
6. 数字用原文数字，不估算；搜索热度要写清比较口径
7. **涨跌一律写百分比，不写倍数**，让不懂数据的人也看得懂：
   - 写「比去年同期 +26%」，不写「1.26 倍」；跌就写「−5%」
   - 和大盘比，写「比大盘多涨 20 个点」，不写「+0.20」；只写「跑赢大盘」不够
   - 例外：本身就是比例的指标（如库存销售比 1.27），照原样写，并说明它是什么
8. 正文不用「C 端」「B 端」这类行话，说「消费者」「消费端」「采购方」

## 六、每期结构和命名

骨架见 `$SKILL/templates/周刊骨架.md`，照着写。

- 四个部分和小栏目的名字固定，不要自创、不要改名：一、本期观点（机会榜 / 行动建议 / 要闻速览）二、市场动向（消费动向 / 采购动向 / 区域速览）三、政策风向（宏观政策 / 贸易壁垒 / 国别风险）四、编辑部手记（下单日历 / 证伪记录 / 下期跟踪）+ 附录（PESTLE 覆盖检查 / 数据源抓取状态）
- 只在四个部分之间用 `---` 分隔，部分内部不加分隔线
- 信号编号用「消费 01」「采购 01」「宏观 01」，每期从 01 重新编号
- 文末署名行照骨架原样保留
- 卡片和折叠用的是 Obsidian 写法，用 Obsidian 打开效果最好；其他 Markdown 软件会显示成引用块，不影响阅读

## 七、文件

| 文件 | 用途 |
|---|---|
| `$P/各期/第NNN期_YYYY-MM-DD.md` | 每期周刊，期号三位数，从第 001 期连续编号 |
| `$P/信号台账.md` | 每期更新，所有信号的状态都记在这里，用来分清持续趋势和一日游 |
| `$P/config.json` | 国家、品类、榜单、板块配置 |
| `$P/选品档案.md` | 适配度打分依据 |
| `$P/数据/` | 折扣热榜、畅销榜和新品榜的原始数据；每期各脚本的输出 `YYYY-MM-DD_脚本名.txt`（判断信号持续了几周要回看），包括官方进口数据 |
| `$P/logs/` | 自动出刊日志 |
